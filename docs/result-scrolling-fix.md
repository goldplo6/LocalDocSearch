# 多文档末项滚动修复与 rc.2 验收

日期：2026-11-12。状态：修复完成；689 项完整回归、100/300 文档真实窗口滚动、rc.2 解压包的公式/面积及 300 文档滚动均通过。本轮交付本地 Windows x64 候选。

## 问题与原因

用户反馈的是很多文档都命中后的最后一个文件。旧 rc.1 的 100 文件、169 处原创语料中，末项可见后展开，会跳回中部文件；最初尚未发送滚轮消息就出现跳动。单文件 70 处的对照通过，故不能把问题仅归结为滚轮冒泡。

外层虚拟化列表根据已实现的行估算整体高度。末项展开改变行高，会改变估算和视口锚点；控件被回收时，原先只存在于 Expander 控件上的展开状态也会丢失。仅加入状态绑定仍是 4 项回归中 1 过、3 败。加入一次展开定位后变为 2 过、2 败，剩余失败发生在全部加载时：加载按钮消失使末项再次缩短。

## 改动

- 文件结果 ViewModel 保存 `IsExpanded`，Expander 双向绑定，展开状态随文件结果而非临时容器保存。
- 主动展开后只排队一次 `Loaded` 定位，布局完成后将该文件带回可见区域；回收恢复已有展开状态时不重复排队。执行前复核仍展开且仍属于当前结果，已收起或新搜索移除的旧结果不拉回。
- “再显示 50 处”在全部加载后保持位置并禁用，避免页尾高度突然缩短。匹配仍按 50 处一批呈现，内外层列表仍虚拟化；未把全部文件控件常驻内存。
- 保持搜索、提取、公式及原文件动作的现有实现。本轮停止原文件自动填词调试。

## 自动化回归

隔离输出完整桌面回归 **56/56 通过，0 失败、0 跳过**，证据：[desktop-final.trx](../artifacts/scroll-fix-validation/results/desktop-final.trx)。其中本轮 6 项覆盖：

- 每次用鼠标实际点击可见加载按钮，分别检查 50 → 100 → 123 处，而不是直接调用两次命令跳过中间布局；全部加载后按钮仍可见且禁用。

## 真实窗口及候选

实际 Windows 窗口已通过以下两组测试，末项均含 70 处匹配：首次展开后滚到第 50 处、加载到第 70 处、触底额外滚动保持展开、滚到顶部使末项容器回收，再返回后仍展开且能重新滚到第 70 处。消息仅发给逐次核验 PID 的自有窗口，没有全局键盘或剪贴板输入。

分发包一组另要求末条文字完整位于匹配详情、结果区和窗口的交集视口，记录了探针 SHA256；没有仅凭 UIA 的 `IsOffscreen=false` 判断可见。上述各组源文件 hash/修改时间均未改变，自有进程正常关闭，未写剪贴板。
