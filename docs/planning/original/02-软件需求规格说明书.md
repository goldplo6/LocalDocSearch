# LocalDocSearch｜软件需求规格说明书（SRS）

> 版本：草案 v0.1｜2026-11-06  
> 面向版本：Windows 11 v1.0  
> 适用对象：开发者、测试者、开源贡献者  
> 关联：[开发阶段与预期成果](01-开发阶段与预期成果.md) · [技术开发方案与选型比较](03-技术开发方案与选型比较.md)

## 1. 背景与产品愿景

用户经常记得文件中出现了“西瓜”等内容，却不记得它位于哪个文件。操作系统内置搜索和打开各类办公软件逐个查找，对多格式混合文件夹、中文内容、反复筛选命中上下文等场景不够顺手。

本软件提供**对本地文件正文的统一、可解释检索**：选一个文件夹 → 输入关键词 → 看到文件级命中和全部上下文 → 展开匹配位置 → 打开源文件，能精确跳转则精确跳转，不能则明确回退。

### 1.1 目标用户

- 本地知识/项目资料管理者、办公室文档重度用户、研发与日志排障人员。
- 默认 Windows 11 桌面环境；开发者本机安装 Office，但公开版不能强制依赖 Office 进行内容读取。

### 1.2 优先级定义

- **P0（必须）**：v1.0 不具备则不达标。
- **P1（建议）**：条件允许优先做，是否进 v1.0 由阶段 0 验证决定。
- **P2（未来）**：明确在 v1.0 范围之外。

## 2. 用户使用流程

1. 启动软件，选择一个或多个待搜索目录中的**一个目录**作为本次任务的根目录；默认递归其所有普通子目录（可在设置中排除）。
2. 输入 `西瓜` 或多个词，如 `西瓜`、`苹果`；通过 **AND / OR** 按钮选择文件级组合逻辑。
3. 选择文件类型（默认全部），点击搜索；显示进度、当前扫描状态，支持取消。
4. 结果分成文件卡片/行，每个文件显示总命中次数；展开后逐条查看上下文、所属字段/工作表/页码/段落/行号；高亮关键词。
5. 选中结果可复制路径、打开文件所在目录；双击某条匹配尝试在关联的 Office/阅读器中定位；失败时仍可正常打开文件并提示位置。
6. 需要调整范围时，进入设置，为具体格式勾选可提取的内容区域，再重新执行搜索。

## 3. 支持范围

### 3.1 v1.0 文件格式清单

| 扩展名 | 类型 | 最低搜索内容 | 最低位置提示 | 备注 |
|---|---|---|---|---|
| `.txt` | 纯文本 | 文件全文 | 行号、列位置（可选） | 识别 UTF-8 BOM/无 BOM 等常见编码 |
| `.md` | Markdown | 源文件文本 | 行号 | 默认搜索 Markdown 源文字，不渲染语义 |
| `.log` | 日志 | 文件全文 | 行号 | 大文件应流式处理 |
| `.csv` | 分隔数据 | 字段文本 | 逻辑记录序号、列序号；能实现则物理行号 | 含换行的引号字段需正确处理 |
| `.docx` | Word | 正文与表格单元格文字 | 段落/表格位置 | 页码可能随排版变化，不作为首选精确源位置 |
| `.xlsx` | Excel | 工作表单元格内容 | 工作表名 + A1 坐标 | 隐藏表、显示值/公式可按配置支持 |
| `.pptx` | PPT | 幻灯片文本框与表格文字 | 幻灯片序号 + 对象提示 | 备注等扩展位置按验证结果启用 |
| `.pdf` | 文字型 PDF | 可提取的页面文字 | 页码 | 不包含扫描图片 OCR |

不含 `.doc/.xls/.ppt`、宏文档其他扩展名、RAR/ZIP 内容、网页、图片、音视频；后续可按插件方式增加。

### 3.2 文件边界与异常

- 默认递归；不沿符号链接/目录联接点无限循环；默认跳过 Windows 系统目录和 Office 临时锁文件（例如 `~$` 开头），具体行为在设置中可见。
- 文件不可读、损坏、加密、无权限、被占用、格式与扩展名不符时，显示“跳过原因/失败原因”，继续扫描其他文件。
- 不自动执行文档内脚本/宏；搜索过程只读。
- PDF 文字无法提取时提示可能为扫描件或受保护文件，**不声称未找到关键词就代表视觉页面中一定没有**。

## 4. 功能性需求

### FR-01 文件夹选择和扫描（P0）

- 支持 Windows 文件夹选择器，记住最近使用目录（仅本机）。
- 搜索根目录及子文件夹；能够停止/取消当前任务。
- 显示已扫描文件数、匹配文件数、匹配位置数、跳过/失败数。
- 对不可访问目录、失效路径、循环目录链接具备错误处理。

**验收**：`D:\资料\项目\计划.docx` 可通过选择 `D:\资料` 找到；遇到无权限子目录不阻断其他路径。

### FR-02 关键词输入与组合逻辑（P0）

- 搜索输入默认是**字面量文字**，不把 `.`、`*`、`(` 等自动解释成正则表达式。
- 支持一个关键词和多个关键词。推荐用“输入后按 Enter 形成关键词标签（chip）”的设计，以避免空格和中文词组的歧义；也可兼容双引号括起来的词组。
- **AND**：当前文件的可搜索内容中必须包含所有**不同**关键词；可分布在不同段落、单元格、页码。
- **OR**：至少包含其中一个关键词。默认 AND；仅一个词时 AND/OR 结果相同。
- 结果中标出每处命中的关键词；统计“文件数”和“出现次数”。默认匹配不重叠的字面量出现；如词组间互相包含，每个词的命中独立记录，最终 UI 按来源区间合并高亮，避免重复算文件。
- 默认对中文进行连续子串匹配，不强制分词；拉丁文字大小写处理规则须明确说明（建议默认不区分大小写，提供开关则为 P1）。
- 当输入框中无有效关键词时，禁止搜索并提示。

**示例**：文件 A 第1页有“西瓜”，第8页有“苹果” → `西瓜 AND 苹果` 命中 A；文件 B 仅有“西瓜” → AND 不命中、OR 命中；`西瓜` 能命中“买了西瓜汁”。

### FR-03 文件格式过滤（P0）

- 可勾选一种或多种支持的扩展名，仅在其范围内进行正文搜索；默认全部支持格式。
- 显示或可查看具体后缀映射；未选任何类型时给予明确提示。
- 过滤应发生在解析前，避免无意义地读取无关文件。

### FR-04 结果列表（P0）

每个命中文件至少显示：文件名、完整路径、文件类型、上次修改时间、当前查询匹配总次数、可展开的全部命中。每条匹配至少显示：包含高亮的上下文、匹配的词、可解释的位置（行号/段落/表格单元格/工作表坐标/幻灯片/PDF 页码等）。

- 支持按文件分组、展开/折叠和继续加载大量命中；不可因单文件大量重复造成 UI 卡顿。
- 上下文推荐以命中前后若干字符或若干行产生，可配置大小；跨段落/单元格时不得拼接出误导性的原文。
- 显示“**匹配文件 N 个、匹配位置 M 处**”，搜索结束与取消状态明确区分。
- 文件名/路径可复制；支持打开文件与在资源管理器中显示文件。
- 排序建议默认路径/扫描顺序，并提供按匹配数、修改时间等排序（P1）；不把不同排序项当作检索相关度。

### FR-05 双击定位（P0：带明确回退）

- 双击命中项时尝试“打开并定位”：
  1. `.txt/.md/.log`：若外部编辑器支持行号定位则传行号，否则默认关联程序打开；内部结果永远显示行号。
  2. `.xlsx`：有 Office 时优先定位工作表 + 单元格；失败时打开 Excel 并提示坐标。
  3. `.pptx`：有 Office 时尝试定位幻灯片；无法选中文字时允许只定位到幻灯片。
  4. `.docx`：优先匹配段落/文字范围；失败时打开 Word 并保留段落提示。
  5. `.pdf`：尽量传页码给可配置阅读器；不支持则打开文件并显示页码。
  6. `.csv`：有可控编辑器时定位记录/行，否则打开文件并显示位置。
- **禁止把“打开文件”表述为“精确跳转成功”。** UI 反馈定位级别：`精确单元格/段落`、`页/幻灯片`、`仅打开文件`。
- 可选择/关闭定位时自动启动 Office；无 Office 环境仍能完成 Office 文件的内容检索。

### FR-06 分格式搜索范围设置（P0 设计，按适配器能力渐进交付）

所有设置项必须遵循能力声明：`支持并可切换`、`尚未支持（禁用）`、`不可用（给出原因）`。

| 格式 | v1.0 首批强制内容 | 待验证后可勾选/后续增强 |
|---|---|---|
| Word | 正文、正文表格 | 页眉、页脚、批注、文本框等 |
| Excel | 普通可见工作表的单元格 | 隐藏表、公式表达式、批注/备注、缓存显示值差异 |
| PPT | 幻灯片正文文本、表格文本 | 备注页、图形组合、批注 |
| PDF | 可提取文字 | 附注、表单等（不包括 OCR） |
| TXT/MD/LOG | 整体文件正文 | 预处理/排除头部等 |
| CSV | 单元格字段内容 | 指定列、跳过表头等 |

- 如果某字段在设置中关闭，新搜索不得匹配其中的文字。
- 若未来使用缓存/索引，改变设置必须失效或更新受影响的数据；不得出现旧配置残留命中。
- 所有影响结果的设置（如隐藏工作表开关）须保存到当前用户配置，并在查询视图可查看。

### FR-07 搜索任务状态与错误（P0）

- 状态：`未开始 / 正在搜索 / 已完成 / 已取消 / 部分完成（有失败文件）/ 失败`。
- 提供进度信息；无法预知总工作量时使用不确定进度提示，而非虚构百分比。
- 单文件提取失败需记录文件名、原因和操作建议；日志不默认复制完整文件正文。
- 限制内存消耗；解析器受异常输入影响不应使整个程序退出。

### FR-08 数据与隐私（P0）

- 默认离线运行；不会上传文件内容、路径或搜索关键词；无默认遥测。
- 只读取被授权选定的文件夹；不得写入原文档；用户设置和可选缓存只存储本机。
- 用户可清除本地搜索记录、缓存和诊断日志（如果将来启用）。
- 文件正文缓存的存储位置和可能泄露敏感内容的风险须在启用前说明；第一版优先不持久化全文内容。

### FR-09 后续能力（P2）

正则表达式模式、邻近搜索、文件大小/修改时间过滤、可配置排除规则、全文索引、增量更新、OCR、旧式 Office 格式、网络共享路径专门优化、跨平台、插件市场等。**不计入 v1.0 承诺。**

## 5. 非功能性需求

| 编号 | 维度 | 要求 | 验证方法 |
|---|---|---|---|
| NFR-01 | 准确性 | 字面量匹配结果必须能在对应提取文本中复现；中文短词不能因索引策略漏报 | 标准测试样本 + 与基线扫描比较 |
| NFR-02 | 交互 | 搜索不阻塞 UI，结果逐步呈现，能取消 | UI 自动/手工操作测试 |
| NFR-03 | 容错 | 失败文档不会中止对剩余文件的扫描 | 损坏/无权限/加密样本 |
| NFR-04 | 稳定性 | 搜索和定位均不改动目标文件；异常不会导致文件丢失 | 搜索前后哈希比对 |
| NFR-05 | 内存 | 超大日志和较大文档采用有界读取/分批结果输出；避免整目录全量驻内存 | 峰值内存与压力测试 |
| NFR-06 | 隐私 | 默认无联网和遥测；诊断日志不包括文件正文 | 网络监视 + 日志检查 |
| NFR-07 | 可维护性 | UI、扫描、提取、查询、定位和存储按接口解耦 | 单元测试与代码评审 |
| NFR-08 | 分发 | 可以从 GitHub Releases 下载安装；给出依赖与已知限制 | 干净 Windows 11 安装测试 |
| NFR-09 | 可访问性 | 高亮不能只依赖颜色，键盘操作可用，文本缩放/高 DPI 基本正常 | 辅助功能与不同缩放率测试 |

性能目标必须在阶段 4 的标准硬件、真实样本、冷/热搜索场景下**测量后批准**；当前不预设无法验证的“10万文件1秒”数字。建议先测：总耗时、每格式解析耗时、开始到首个结果的延迟、峰值内存、取消延迟、失败率。

## 6. 搜索结果数据契约（逻辑模型）

```text
SearchRequest
  rootFolder
  terms[]              # 用户明确输入的字面量词组
  operator             # AND | OR
  allowedExtensions[]
  extractionOptions     # 各格式可搜索区域开关

FileResult
  absolutePath, extension, modifiedTime
  totalOccurrences
  matchItems[]
  extractionWarnings[]

MatchItem
  matchedTerm
  excerptBefore, highlightedText, excerptAfter
  sourceLocation       # line | paragraph | sheet+cell | slide | pdfPage ...
  confidence/level     # 精确位置 | 页级/段级 | 仅上下文
  sourceSegmentId
```

`totalOccurrences` 是实际记录的字面量匹配出现次数；同一文件在文件级结果中仅出现一次。设置或匹配策略改变后，必须重算符合本次请求的结果。

## 9. 风险、歧义和决策项

1. **“显示值”不等于文件实际存储值**：XLSX 公式可能只有公式和过期缓存，没有最新运算结果。v1.0 应对“缓存结果/公式文本/原始值”分别标注，不承诺脱离 Excel 重新计算所有公式。
2. **Word 的真实页码非稳定源属性**：排版受字体、打印机、节等影响，以段落或文字范围作为主定位。
3. **PDF 阅读顺序不总可靠**：复杂多栏、表格和断行可能造成提取文本顺序与视觉位置不同；保留页码并提示限制。
4. **Office 自动化依赖安装版本与安全策略**：只有内容解析与 Office 自动化定位解耦，才能让无 Office 用户正常搜索。
5. **跨文件 OR/AND 定义**：AND 在“文件级”，不是同段、同页或同单元格；一旦加入邻近查询，应单独命名。
6. **开源项目名称**：`LocalDocSearch` 是暂定名，公开发布前检查重名、商标及仓库可用性。
