# 定位选中、紧凑界面与长文档验证

本轮反馈已完成：补充可核验的只读文字预览与自动选中，改进 Word/PPT 原程序文字定位，将结果区保留为窗口主体，并交付可直接打开的超长文档。未启动第五阶段发布工作。

## 1. 使用方式与定位边界

- 点击文件行或匹配详情的“定位并选中”，或双击结果，打开独立的只读文字预览；读取八种格式均无需启动 Office。
- 预览重新使用搜索当时的编码与提取范围，核对来源片段 ID、完整结构位置、原始 UTF-16 偏移及命中前后文；读取完整文件后才展示。文件修改时间不符、前后元数据变化、片段重复或来源失配时报告定位未完成，不改选同词的第一处。
- 预览仅保留目标片段，最多显示命中附近 24,000 个 UTF-16 字符。TextBox 为只读，设置实际选区后读回所选文字，核验一致才显示“已选中”。没有永久全文缓存或源文件写回。
- PDF 显示真实来源页码和该页的提取文字。例如“PDF 页码 200（页内提取文本）”；它不还原原 PDF 排版。
- 展开结果后的“原程序定位”保留独立动作。Office 自动化仍默认关闭，需在“搜索设置…”中开启；默认程序打开只表示 `OpenedOnly`。

| 原程序来源 | 当前能力 |
|---|---|
| Excel 单元格 | 完整路径、工作表、合法单格地址及实际选区一致时 `Exact` |
| Word 正文 | 段落、唯一上下文、偏移、实际文档路径及完整文字选区均核验后 `Exact` |
| PPT 顶层文本框 | 文稿、页序、对象、段落及实际文字选区均核验后 `Exact` |
| PPT 表格或文字选区未核验 | 页序已核验时保留 `Section` |
| Word 表格、修订文档、目标段落含字段或上下文歧义 | 保守降级，不猜选首次同词 |
| 任意默认 PDF 阅读器、普通文本编辑器 | 原程序仍为 `OpenedOnly`；使用应用内预览完成本次文字选中 |

原程序 `Exact` 表示已读回位置证据，不保证搜索后整个文档版本从未变化。预览的元数据与命中上下文检查也不是内容签名或一致性快照；同长、同时间且保留目标上下文的修改仍有边界。Office 新开保护视图、多版本、多实例及复杂结构继续单列验证。

## 2. 界面面积实测

主窗改为紧凑的目录、关键词、搜索操作和状态行；关键词横向滚动，64 个长词不会增加顶部高度。格式/大小写进入弹出菜单，说明、预算、诊断与文件能力提示收在圆形“!”入口。文件行直接显示首条命中上下文和定位按钮，结果与详情仍采用原生虚拟化列表。

实际 Windows 窗口在 125% DPI 下，分别测量空关键词和 64 个长关键词。外框面积采用 Win32 `GetWindowRect`，客户区采用 `GetClientRect`，结果区采用实际 UIA 几何；不是只依据 XAML 星号比例估算。

| 目标逻辑尺寸 | 关键词数 | 结果区 / 客户区 | 结果区 / 整个窗口外框 |
|---|---:|---:|---:|
| 850 × 640 | 0 / 64 | 69.30% | **64.36%** |
| 1140 × 820 | 0 / 64 | 74.89% | **70.55%** |
| 1600 × 900 | 0 / 64 | 77.41% | **73.51%** |

六组均超过 60%。尺寸为缩放操作的目标逻辑尺寸，最小尺寸约束和系统边框以实际测量为准。另有相同三尺寸、64 个长词的 Avalonia 布局回归。

实际面积及预览记录：[UIA v2 报告](../artifacts/history/records/navigation-preview-uia-v2.json)。早期报告把 UIA 根窗口边界当作外框，不能用于外框比例结论；本表仅使用 v2 的 Win32 外框测量。截图已保存，未作人工视觉审阅；多 DPI 和完整键盘/IME 体验继续留待专项验收。

## 3. 可直接打开的超长文档

样本位于 [long-documents 目录](../tests/fixtures/long-documents)，合计约 4.87 MiB。它们验证页数、晚位置、重复词和来源，不替代第四阶段的 64/128/256 MiB 大字节性能负载。

| 文档 | 规模 | 重复词“长文定位西瓜”的位置 |
|---|---|---|
| [200 页 PDF](../tests/fixtures/long-documents/原创长文档-200页.pdf) | 实际 200 页 | 第 150 / 200 页 |
| [200 内容页 Word](../tests/fixtures/long-documents/原创长文档-200页.docx) | 2,400 正文段、199 个手动分页符 | 正文段落 1,798 / 2,398 |
| [100,000 行 TXT](../tests/fixtures/long-documents/原创长文本-100000行.txt) | UTF-8，无 BOM | 第 75,000 / 100,000 行 |
| [20,000 条记录 CSV](../tests/fixtures/long-documents/原创长表格-20000记录.csv) | 加表头共 20,001 行，3 字段 | 含表头记录 15,001 / 20,001，第 3 字段 |

Word 的内容分页不是对任意字体和打印环境的实际排版页数承诺；PDF 则逐页读回确认 200 页。DOCX 经 OpenXmlValidator 验证为 0 错误。

实际提取/搜索读回：

- “长文定位西瓜”：4 文件、8 处。
- “长文末尾定位”：4 文件、4 处。
- “苹果”：0 文件、0 处。
- 跨 Word 段拼接的 `LD_DOCX_P200_ANCHOR长文末尾定位`：0 处，没有跨片段造词。

在实际窗口搜索“长文末尾定位”，依次打开四个结果，预览成功显示只读内容并报告选中 6 个字符：PDF 第 200 页、Word 正文段落 2,400、TXT 第 100,000 行/列 26、CSV 含表头记录 20,001/字段 3。源文件前后 SHA256、长度与修改时间一致。

本机 Avalonia 的 UIA TextPattern 不可用，因此外部 UIA 没有独立读取文字选区；实际窗口报告核验了 ValuePattern 只读属性、内容和应用内部选区读回后的状态。另用真实 TextBox 的自动化回归直接断言 `SelectedText` 为指定的第二次同词，而不是第一处。两种证据分别记录，不把应用状态误称为外部选区读回。

## 4. 原程序实机核验与 Word 修复

独立探针仅将原创源文件复制到 GUID 目录，在 Word 副本中预先追加诊断段落，随后以正常只读窗口打开副本，调用正式导航器。另行读回实际 COM 文档、结构和选区，7 项均符合预期：

| 场景 | 实际结果 | 独立证据 |
|---|---|---|
| Word 正文“西瓜” | `Exact` | 段落 1，绝对范围 5–7 |
| Word 正文前缀“原创” | `Exact` | 段落 1，绝对范围 0–2 |
| Word 600 字长词 | `Exact` | 段落 3，范围 26–626，完整 600 字 |
| Word 唯一上下文中的第二个“苹果” | `Exact` | 段落 4，段起点 634 + 偏移 6 = 范围 640–642 |
| Word 相同上下文中重复“苹果” | `OpenedOnly` | 原段落 4 的选区保持不变；未猜选目标段落 5 的首次同词 |
| Excel `Sheet2!B15` | `Exact` | 实际 Sheet2、`$B$15`，单元格值“西瓜” |
| PPT 第 8 页“西瓜” | `Exact` | 页 8、对象序号 2/名称“正文”、ShapeId 3、段落 1，选中文字“西瓜” |

实机发现 Word `Find` 对恰好等长的短范围可能返回 false，或跳到范围外下一同词。对照记录中，0–2 的“原创”漏查，640–642 的第二个“苹果”跳到 645–647；只把查找探针右界增加一个字符、且不越已核验段落，恢复了预期起点。完整选择范围保持原始命中边界，仍核验段落、唯一上下文、起点、长度和完整文字，另补 5 个边界回归。

[最终严格实机记录](../artifacts/history/navigation/native-selection-2d6cc76f6aa64d00baa0e00a66eb9a14/navigation-selection-report.json)中，6 个 `Exact` 均有独立位置与文字证据；歧义例 `IndependentAgreement=false`、`SelectionUnchanged=true`，不把上一处同词选区算作新目标成功。源文件及制备后的副本 SHA256、长度与修改时间全部不变。

三个测试副本均正常关闭，既有 Word/Excel 窗口保持。探针因 COM 句柄读取失败保留了测试创建的空 PowerPoint 实例；父流程随后按已记录的 PID、精确启动时间、实际主窗句柄及空白标题再次核验，调用 `CloseMainWindow` 正常退出。没有强制终止进程或关闭其它 Office 窗口，见[独立清理记录](../artifacts/history/records/navigation-probe-cleanup.json)。本轮验证的是预先只读打开的普通 Office 副本，未把它等同于新开保护视图下的选择能力。

## 6. 重现入口

```powershell
./scripts/dev.ps1 -Action Run -Locked
```

选择长样本目录，搜索“长文末尾定位”，点击“定位并选中”。原程序 Office 选择需先在设置中开启自动化；PDF 的主要定位入口使用应用内只读文字预览。

开发者可重跑 [窗口预览与面积探针](../artifacts/history/tools/navigation-preview-uia.ps1) 和 [原程序独立选区探针](../artifacts/history/tools/navigation-selection-probe.ps1)。UIA 探针报告使用 CreateNew，已有报告应先保留并为新轮次指定未占用的输出名；不覆盖历史证据。原程序探针使用新的 GUID 目录与独立记录，不保存源文件。
