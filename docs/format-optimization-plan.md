## 验证与采纳

1. 对照基线覆盖文本、ID、来源、顺序、警告、异常与整文件发布边界；保留既有测试强度并新增关键边界案例。
2. 只由父执行构建和测试，避免并行构建污染。依赖锁和 NuGet 不扩张；使用项目本地 .NET SDK。
3. 同一基准 driver，旧版与试验版仅替换 Core / Extractors DLL。采用串行 ABBA，保存正负结果和原始样本；结果 SHA 放在计时外，分别记录引擎耗时、CPU、分配和进程生命周期峰值。
4. 共享缓冲释放另做消费中存活内存实验。它不能降低先完整提取所需的峰值，避免把消费期改善宣传为提取阶段峰值下降。
5. 无收益、有明显回退或语义难以等价的候选不并入最终产品；记录原因，不用合成样本推断所有实际文档收益。
6. 最终运行完整回归、原生查询/预览/滚动/暂停停止与独立验包，更新实际验收结论和根启动入口。

## 实际取舍

- 采纳 CSV 普通和引号内连续文字处理；首轮引号回退经修正后，实际包 9 个 CSV 场景均有收益。
- 采纳 Excel 与 Word 的完整 XML 预检加小结构读取、PPTX 简单段落快路。明确保留 Word 正文稀疏搜索 +3.09% 的局部回退，以及 Excel 直接提取累计分配增加约 49—66 MiB 的代价。
- 采纳完整提取后及时清除已消费 Office／PDF 段引用；用消费中存活量和旧版预期失败作证，不宣称完整提取峰值降低。
- 撤回没有稳定收益的文本行拼接候选；未采用会改变失败或取消边界的直接 Decoder。TXT／MD／LOG 源码及 PDF 提取算法保持原样，没有 PDF 稳定提速结论。
- 保留首轮比较器误报的原始失败报告、独立 reconciliation 和四工作者额外探针未完成证据；最终实际包的 45 场景报告自身通过，默认单工作者四控制场景全部通过。

既有边界仍有效：八格式只读、无 OCR / 索引 / 跨轮全文缓存；工程资源预算不是进程硬内存上限；同步 Office/PDF 解析不保证即时取消。详见[逐格式评审](performance-opportunities-review.md)和[搜索原理](search-principles-and-next-steps.md)。
