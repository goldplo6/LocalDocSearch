# 技术决策记录

## ADR-001：优先验证 C# + Avalonia + CommunityToolkit.Mvvm

- 日期：2026-11-06。
- 状态：用户同意第一阶段验证路线；正式发布框架基线待原型验收。
- 背景：目标首先是 Windows 11，同时重视未来生态适应与跨平台空间。核心搜索、文档解析和 UI 必须解耦。
- 决策：以 Avalonia 构建首个原型；采用 CommunityToolkit.Mvvm；先建立 Desktop/Core/Tests，再按复杂度拆分模块。
- 理由：解析层可继续使用 .NET 库；ViewModel 尽量不依赖具体 UI 控件；Office COM 留在 Windows 适配边界。
- 控件策略：基础 Fluent 控件、ListBox 虚拟化和命中分批展示；首阶段不依赖商业高级控件或付费开发工具。
- 验证：中文 IME、高 DPI、键盘、上下文高亮、一万条结果、取消响应和 Office 定位分别记录证据；Headless 结构测试不替代真实桌面输入体验。
- 原规划解释：原三份文档为历史草案，其中 WPF 是当时首选；本记录覆盖“当前优先验证 UI 路线”，不代表其余候选比较已实测。

## ADR-002：第一阶段直接扫描 TXT/MD/LOG

- 状态：原型实施基线。
- 搜索语义：默认不区分大小写的字面量匹配；AND 为文件级，OR 任一词；每词独立非重叠计数；结果保留源文件行列与原文上下文。
- 编码：支持严格 UTF-8 与带 BOM 的 UTF-8/UTF-16/UTF-32；其他编码本阶段明确报读取错误，GB18030 回退后续验证。
- 数据：只读源文件，不持久保存文件正文、路径、搜索关键词，不添加遥测。
- 已知边界：按行流式读文件；极长单行与单文件海量命中的内存上界仍需下一轮性能设计；不提前承诺百万文件或固定秒级性能。

## ADR-003：可复现构建与许可边界

- SDK：10.0.403；官方 release metadata 核验时间 2026-11-06。
- Avalonia/Avalonia.Desktop/Avalonia.Themes.Fluent/Avalonia.Headless.XUnit：12.1.5。
- CommunityToolkit.Mvvm：8.4.2。
- 测试：Core 使用 xUnit 2.9.3；Desktop 使用 xunit.v3 3.2.2 和可执行测试宿主，以匹配 Avalonia.Headless.XUnit 12.1.5 的实际 v3 依赖。两者共用 xunit.runner.visualstudio 4.0.1、Microsoft.NET.Test.Sdk 18.11.0；按独立测试程序集运行。
- 兼容性证据：曾用 v2 桌面测试工程导致测试发现失败；按包内官方 nuspec 对齐后，Core 39 项与 Desktop 5 项均通过。
- 依赖集中固定于 Directory.Packages.props，生成 packages.lock.json；版本选择来自 NuGet 官方 flat-container API，实际兼容性以 restore/build/test 为准。
- 本机原来只有运行时；SDK 下载到 .tools/dotnet，验证官方 SHA-512，不修改系统 PATH；开发脚本关闭 CLI 遥测。
- 许可证：项目 MIT/Apache-2.0 尚未最终选择。引入包的许可及完整传递依赖需要发布前逐项核对；不引入 TreeDataGrid、Accelerate 或 DevTools 商业组件。

## ADR-004：第二阶段统一片段与八格式适配

- 日期：2026-11-09；状态：已实施，证据见[第二阶段报告](phase-2-results.md)。
- Core 保持无第三方依赖；ITextExtractor 输出 TextSegment/SourceLocator，Core 内含纯文本与 CSV，新增 Extractors 模块集中 Office/PDF。Desktop 注入完整注册目录。
- 固定 DocumentFormat.OpenXml 3.5.1、PdfPig 0.1.16；官方 NuGet nuspec 的直接许可分别为 MIT、Apache-2.0。直接包元数据核对不代替完整传递依赖及分发审查。
- 搜索在片段内做字面量匹配，AND/OR 在文件级汇总；结构间不拼词，同段 run 可合并。保留稳定片段 ID 与零基 UTF-16 偏移，显示来源从 1 开始。
- Word 使用正文段落/表格结构位置，不猜页码；PPT 按演示关系顺序；PDF 按页。XLSX 默认只读可见普通表，标明存储值/公式缓存，不计算、不冒充格式化显示。
- 固定搜索范围及提取限制在窗口和结果中声明；能力警告独立于错误，仍使本次状态标为部分完成，以免把有限覆盖当作完整文档搜索。
- Office/PDF 只读打开并整文件原子发布。输入 128 MiB、Office 单 part 16 Mi 字符、累计输出 32 Mi UTF-16 字符/200000 片段；超限报错，不静默截断。第三方单次同步解析及所有结果的总体内存仍需后续性能设计。
- 文件打开继续标明不定位；COM、OCR、索引、持久逐格式设置留待后续，未扩大本轮交付。

## ADR-005：第三阶段可选编码、本地偏好与证据分级

- 日期：2026-11-09；状态：已实施，证据见[第三阶段报告](phase-3-results.md)。本记录更新 ADR-002/004 中编码、偏好与打开动作的阶段边界。
- 原 CSV 为合法 UTF-8，错误显示不等于原文损坏。默认仍严格 Unicode；可选 UTF-8 完整校验失败后严格 GB18030 回退、或无 BOM 强制 GB18030。BOM 永远优先，兼容仅影响文本/CSV；不猜测丢失文字、不写回源文件。回退有警告，不冒充全面覆盖。
- 编码校验在同一只读流中分缓冲进行，校验完成后回到起点提取；保持文件级原子发布与取消语义。CodePages 使用 .NET 自带支持，不增加包依赖。
- 新增 Settings 模块：版本化 JSON 只保存偏好，包括根目录，排除关键词/正文/结果；同目录临时文件替换。损坏配置保留并提示，自动保存不覆盖，只有显式保存可替换。
- 逐格式范围采用不可变 DocumentScopeOptions；每次查询使用编码/上下文/范围快照。关闭区域不匹配，来源编号和 ID 保持稳定，未实现区域仍禁用。
- 新增 Windows Navigation 模块，与解析分离。默认仅关联程序 OpenedOnly；Office opt-in 只在用户打开匹配时启动。新开自动化文档使用保护视图；既有文档保留原状态；不修改 Office 设置、不保存、不关闭。
- Exact 限于 Excel：实际读回完整路径、Ordinal 工作表名、规范化合法单格 A1 地址全部一致。PPT 仅在完整文稿路径和幻灯片序号一致时 Section，不宣称文字 Exact；Word 保守 OpenedOnly。等级表示位置核验，不保证旧搜索后源文件未变。
- Office COM 在后台 STA 中执行，全应用单调用门闩，等待上限 12 秒。超时/忙明确 Failed，不重复打开；取消只停止等待与后续步骤，不终止用户 Office 或已发出的 COM。
- 本机实际只读副本验证：Excel B15/D20 为 Exact，错误表名为 OpenedOnly，PPT 第 8 张为 Section；原文件与副本哈希/修改时间未变。全套 312 测试通过。保护视图新开、多实例、多版本与无 Office 干净机仍单列验证。

## ADR-006：第四阶段有界资源、背压与可复现基线

- 日期：2026-11-09；状态：已实施，证据见[第四阶段报告](phase-4-results.md)。更新 ADR-002/004 中资源预算待设计的阶段边界，搜索语义、编码与导航等级保持原约定。
- Core 注入不可变 SearchResourceLimits：单段 1,048,576 字符、每文件 50,000 处、整轮 200,000 处/20,000 命中文件、100,000 候选文件、待扫描目录 20,000/深度 128。长度及命中预算在追加/分配之前检查，第三方产出在 Engine 再核验。单文件超限整份失败；全局真正出现额外合格项才 Limited，恰限完成仍 Completed。
- 原始错误/警告计数独立于有限详情：全局 1,000 条、每文件 100 条警告，另保留省略聚合说明。用类型化问题代码区分编码、权限、损坏、资源限制与来源变化；保存的代码分布只代表保留详情。
- 源文件大小/mtime 或最终重解析属性变化时放弃整份结果，不冒充一致性快照；同长同时间修改及检查后竞争仍保留边界。
- 桌面使用容量 64 的结果通道及容量 256 的诊断通道，满时等待；60 ms 定时、4/8 ms 软处理时间片。取消解除结果背压、逐项停止展示，已接收诊断及最终聚合继续排空。排序只通知一次 Reset，详情与诊断采用虚拟化视口。
- 聚合诊断由用户主动复制，不含目录/文件路径/关键词/正文/异常原文和原始限制原因，不自动落日志、不发送遥测。偏好保存范围仍按 ADR-005。
- 原创基准带所有权标记、清单和前后 hash/长度/mtime 核验；串行三轮，首轮和重复分别报告，预校验暖缓存，不称冷启动缓存测试。生命周期峰值、托管分配、Core 计数回调与真实 UI 保留结果分别解释。
- 实测发现固定大缓冲导致小文件分配增加，改用清理后归还的缓冲池与分隔符快速扫描。最终小文件重复 1,354.02 ms，仍慢于第三阶段 1,016.12 ms；保留初版 1,620.01 ms 及原始证据，不声称整体加速。后续优化先 profile，再决定索引/缓存。
- 最终 478 项回归全通过；实际窗口验证 5,000 文件、200,000 处、1,200 错误和取消恢复，当前仅 125% DPI。文件行辅助功能名称绑定标题；原生 End 可达末文件，根 ScrollPattern 仍未具备完整能力。另有实际 460 字符中文路径、NTFS 目录循环及 ACL 访问失败验证，原始源与 ACL 恢复核验通过。
- 上述护栏不等于解析器/进程硬内存限制，亦不保证同步解析即时抢占。人工体验、干净机、Office 矩阵、许可与分发继续单列。

## ADR-007：可核验文字选中与紧凑结果界面

- 日期：2026-11-09；状态：已实施，证据见[定位、界面与长文档报告](navigation-preview-results.md)。按实际能力扩展 ADR-005 的定位边界，未启动第五阶段发布工作。
- 主“定位并选中”使用独立只读文字预览，无需 Office；重用搜索时编码/范围，完整重读后核对片段 ID、结构来源、原偏移及前后文。元数据变化、片段重复或来源不符即报告未完成，不全局猜选第一处同词。最多显示附近 24,000 字符，实际 TextBox 选区读回一致才报告选中；PDF 标注真实来源页码，不还原原排版。
- 原程序入口保留且 Office 默认关闭。Word 正文和 PPT 顶层文本框在结构、唯一上下文、路径与实际完整文字选区一致时可 Exact；Excel 的原单格规则不变。Word 表格/字段/修订和歧义保守降级，PPT 表格保留 Section，任意默认 PDF 阅读器仍 OpenedOnly。实际只读普通窗口不等同于新开保护视图。
- 实机发现 Word 等长短 Find 范围漏查或跳到下一同词；仅增加不越段落的一个后继字符用于 Find 探针，完整 Select 仍保留原边界。补 5 个边界测试，并独立读回 6 个 Exact 与 1 个正确降级例；第二“苹果”核验绝对范围而非只比较文字。
- 顶部固定紧凑行、关键词横向滚动，说明/能力/预算收圆形“!”；结果保留虚拟化。125% DPI、三尺寸、0/64 长词共六组，结果区占 Win32 整窗外框 64.36%–73.51%，最小场景也超过六成。
- 新增实际 200 页 PDF、含 199 手动分页符的 2,400 段 Word、100,000 行 TXT、20,000 记录 CSV，真实晚来源与重复词回读、哈希/mtime/长度核验。完整回归 538 项通过；UIA TextPattern 不可用，外部只读内容/状态证据与直接 TextBox 选区测试分别说明，未宣称截图视觉验收。
- 搜索语义、只读约定、源文件非快照边界、Office 共享 STA 门闩、预算与隐私约定保持。既有 Office 窗口不保存、不关闭；测试自有副本和确认归属的空 PowerPoint 窗口已正常清理。

## ADR-008：逐项查询公式、原文件查找辅助与隔离候选构建

- 日期：2026-11-10；状态：已实施，本地候选验收通过；默认 Acrobat 自动填词尚未通过实机验收，证据见[第五阶段报告](phase-5-results.md)。
- 每个新增词保存自己的前置 AND/OR；AND 优先于 OR，顶部按相同格式器显示必要括号。连接仍在文件级计算，原有纯 AND/OR 请求兼容，关键词内的 AND/OR 保持字面量。查询与连接不写入设置。
- 原文件查找与原程序定位分开反馈。只在目标完整路径、固定前台窗口及明确查找控件均核验后填词并读回；查找框成功只报告 SearchFieldFilled，不声明 Exact。不支持或证据不足时保留手工查找词，自动流程不触碰剪贴板。
- 所在目录改用 Windows Shell PIDL 选择文件，移除 explorer.exe 命令行调用。接口成功与具体杀毒产品的告警分别验收，不修改杀毒设置。
- 项目选择 MIT，保留依赖原有条款与原文证据。发布采用白名单源码快照、源锁验证、候选专用 RID 锁及自带运行时文件夹 ZIP；不裁剪、不 AOT、不单文件打壳。保留输入、包/运行时哈希、TRX 和分发清单；独立干净构建字节一致性另行验收。
- 运行中的旧程序保持不动；独立输出解决 Windows DLL 文件锁。本地候选不代表公开发布、代码签名或干净机验收完成。

## 仍待验证或决定

1. 人工 IME、多 DPI、完整键盘/滚轮、辅助功能矩阵与截图视觉体验；已有单一 125% DPI 的实际 5,000 文件及 End 导航证据见第四阶段报告。
2. 更复杂真实文档的提取覆盖，以及 XLSX 格式化显示值的额外实现方案；当前存储值/缓存语义已锁定并回归。
3. Word 表格等复杂结构、新开保护视图/多实例/Office 版本矩阵及无 Office 干净机；已有 Word 正文、PPT 顶层文字和 Excel 单格的实际选区证据见定位报告，注册存在不等于定位成功。
4. 预算已实施；继续测量真实复杂文档、解析器峰值与吞吐开销，依据 profile 判断缓存/索引是否必要。
5. 项目 MIT 及实际 30 个 NuGet 包/自带运行时许可证据已落实；公开发布、签名、真正干净 Windows/无 Office 环境、安装程序与真实 360 检测仍待验收。
6. 默认 Acrobat 首次条款弹窗处理后的自动填词，以及兼容浏览器查找控件的真实读回；当前只有条件适配与回归证据，本机未取得自动填词成功。
