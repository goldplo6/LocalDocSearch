# 第一阶段计划：Avalonia 路线验证与文本搜索原型

日期：2026-11-06。状态：计划、原型与自动验证已完成；人工交互与 Office 定位实验按清单待验收。实际证据见[验证报告](spike-results.md)。

## 目标和边界

用户同意优先验证 C# + Avalonia + CommunityToolkit.Mvvm。本阶段整合原路线图的“阶段 0 必要验证”和“阶段 1 文本穿透原型”，不等同于 v1.0 完成。先取得可以构建、运行和测试的原型，再决定是否批准 Avalonia 为正式 UI 基线。

交付 TXT/MD/LOG 的递归只读搜索；默认字面量、不区分大小写、文件级 AND；允许切换 OR、区分大小写、文件类型。每个文件汇总全部匹配，逐项显示行列与上下文；搜索在后台运行，可取消，失败文件可查看。

本阶段不交付 DOCX/XLSX/PPTX/PDF/CSV 提取器、全文索引、全文持久缓存、OCR、安装包或 Office 精确定位。设置页不得显示尚未实现的能力为已支持。用默认关联程序打开只表示打开文件。

## 关键验收用例

- “西瓜”命中“西瓜汁”；一、二、三字中文均不依赖分词；输入 `.*` 按普通文字查找。
- 同一文件两行分别有“西瓜”“苹果”，AND 命中；分别位于不同文件时 AND 不命中；OR 均返回。
- 同一文件 50 次匹配只产生一个文件结果，完整记录 50 次；关键词去重并明确各词独立计数。
- 文件扩展名在读取前过滤；中文路径、空格路径、UTF-8 和带 BOM Unicode 文本正常处理。
- 非法编码、权限或读取失败有原因；已取消与已完成状态有区别；不保存或修改源文件。
- 大列表不创建一万个可视结果控件；单文件大量匹配分批展示，完整数据计数保持真实。
- 打开与定位文案准确；首阶段仅实现系统默认程序打开及所在目录打开。

## 退出关口和下一阶段

自动构建与回归测试通过后，将本阶段标记为“自动验证完成，人工交互项目按清单确认”。中文 IME、DPI、真实 Office 定位没有实测证据时保留待测，不用 Headless 结果替代。

下一阶段优先实现统一 TextSegment/SourceLocator、八格式原创样本、Open XML 与 PDF 提取，并实验 Excel 原始值/公式/缓存值语义；Office 定位继续作为独立 Windows 模块。缓存与索引以性能测量为依据，不预设文件数量阈值。

项目许可证仍待 MIT/Apache-2.0 决策和完整转依赖审查；原型可本地开发，不提前宣称已具备公开发布条件。
