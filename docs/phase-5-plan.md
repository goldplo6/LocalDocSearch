# 第五阶段计划：原文件查找、查询公式与本地发布候选

状态：2026-11-10 本地候选与解压验收已完成；P5-01 的默认 Acrobat 自动填词仍未通过实机验收。第四阶段与上一轮定位预览报告保留为历史验收；本轮逐项结果见 [第五阶段报告](phase-5-results.md)。

## 1. 目标与判断口径

1. 原文件查找优先请求原程序的查找功能；只向已经核验的目标窗口/查找控件输入词。证据不足时显示明确的手工查找步骤，不把键盘动作或查找框内容当作精确来源选区。原有只读预览与 Office 已核验定位保留。
2. 所在目录改为 Windows Shell PIDL 接口选择文件，移除通过 PATH 查找 explorer.exe 和拼装命令行参数的实现。360 警告的具体规则需用户侧告警证据或实际检测确认，本阶段不宣称消除任何杀毒告警，也不修改杀毒设置。
3. 显示与实际计算一致的公式，支持逐项 AND/OR。AND 优先于 OR；例如 `(西瓜 AND 苹果) OR 荔枝`。关键词本身保持字面量，不把单个关键词内的 AND/OR 当运算符。
4. 实施原路线图第五阶段的本地发布准备：许可证选择、实际依赖清单、使用/隐私/贡献/变更/问题报告文档、手动 CI、Windows x64 自带运行时的可解压候选包、SHA-256 与可复现输入记录。

公开 GitHub 仓库、远程发布、版本标记、代码签名和真正干净 Windows 11 机器验收需要各自真实条件；本次先交付本地候选制品与明确的剩余关口，不把候选准备等同公开发布完成。

## 3. 实现约束

- 保持八格式源文件只读、不添加 OCR/索引/全文缓存，不改变资源限额、取消与完整文件结果语义。
- 原程序查找与 `Exact/Section/OpenedOnly/Failed` 原生定位分开描述；查找框成功不意味着找到第几次同词。
- 尽量不触碰个人剪贴板；手工复制只能由用户明确点击触发。目标不明时不全局发送 Ctrl+F/Ctrl+V。
- 结果区域仍至少占整窗 60%；公式放在现有工具栏，保留圆形 ! 帮助与虚拟化列表。
- 现有单纯 AND/OR 请求兼容；新增连接逐项保存于本次查询，不持久化关键词或查询正文。
- 不执行 git init/commit/push 或远程发布，不引入打包壳、提权、杀毒排除或未知下载器。
- 许可默认选择 MIT，依赖保留各自条款；发布候选的许可证据与分发清单必须能审阅，不以脚本成功代替专业法律审核。

## 4. 发布关口

本地候选验收和公开 v1.0 验收分别记录。后者仍须确认仓库与维护者信息、干净 Windows/无 Office 环境、真实 360 提示、签名与发布渠道。哈希用于验证下载内容一致性，不能单独证明无误报或无风险。构建记录区分锁定输入、同环境重复构建与跨干净环境字节完全一致。
