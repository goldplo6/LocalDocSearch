## 高级搜索语义与边界

- 普通主窗口输入保持字面量，不因新增功能开始解析 AND、OR、括号或正则。
- 逻辑页沿用整文件 AND/OR 资格判断。手写支持 AND/OR（大小写无关）、括号和双引号文字；AND 优先于 OR，相邻文字须明确连接。含空格、运算符或括号的关键词用双引号；反斜杠转义与规范公式往返保持文字一致。重复词保持位置身份，匹配不重复计数。
- 无效、未闭合、缺操作数/连接、非法转义、空式或超限公式显示明确错误及 UTF-16 位置；应用入口与命令再次验证，不回退执行旧公式。取消才恢复主查询。可视化与手写共享表达式树并可双向切换。
- 手写公式最多 262144 个 UTF-16 单位，词数与词长沿用查询预算；树最多 128 层、256 个节点。解析和验证在文件访问前完成。
- 正则页使用标准 .NET 正则语法，独立于逻辑词表；支持整体匹配，显示真实命中文字及来源。按单个提取片段匹配，不拼接独立段落、页面、单元格；零长度匹配跳过，不产生伪造选中范围。
- 正则最长默认 4096 UTF-16 单位；单次匹配超时预算默认 100ms、单文件累计匹配预算默认 1000ms，并沿用所有命中数/文件数/片段预算。超时检查和取消有粒度，不是进程硬实时限制。超时文件丢弃完整结果、记录去敏错误并继续其他文件。
- 语法错误或模式混用在扫描前阻止执行。搜索期间禁止修改/应用，保留待添加输入保护。关键词、手写内容和正则不进入偏好、聚合诊断或日志；预览与外部查找使用真实匹配文字，不把正则当作源文。

## 实施及验收顺序

1. 并行实现独立逻辑解析器、受限正则引擎和双页界面，固定公共契约，父流程统一串行隔离构建。
2. 新增语法、转义往返、资源边界、零长度/超时/取消、真实位置和主查询模式的测试；保留现有 752 项回归及真实控件断言。
3. 定稿候选使用说明与变更说明，生成新版本本地候选，保留 rc.3。
4. 独立解压，用自有测试窗口/语料验证逻辑和正则实际搜索、错误阻止、取消、来源预览、旧公式/布局与滚轮；核验源与包运行前后哈希、偏好和路径泄漏。
5. 直接继续第 2 步交互验收，修复有证据的输入/键盘缺陷，记录真实 Windows 环境覆盖。环境缺失如实列出，不把本机或合成测试改称干净机/实际输入法验收。
