## 初始资源策略

这些是明确可诊断的工程护栏，不是已批准的速度 SLA，亦不是第三方解析器/进程总内存硬限。Core 的不可变 SearchResourceLimits 由构造参数提供，桌面默认启用，不把它们伪装成用户已搜索完整的阈值。

| 预算 | 默认值 | 超限行为 |
|---|---:|---|
| 单段/物理行/CSV 字段 | 1,048,576 UTF-16 字符 | 整个当前文件失败，继续其它文件 |
| 每文件匹配 | 50,000 | 整文件失败，不取前 50,000 处冒充完整 |
| 整轮匹配 / 命中文件 | 200,000 / 20,000 | Limited，保留已完整发布文件，说明扫描未完 |
| 完成或失败的候选文件 | 100,000 | 后续仍有候选时 Limited |
| 待扫描目录 / 深度 | 20,000 / 128 | 明确报告遍历边界，不静默跳过 |
| 全局诊断详情 / 每文件警告 | 1,000 / 100 | 完整总数，有限详情及明确聚合说明 |
| 关键词 / 每词长度 / 每侧上下文 | 64 / 4,096 / 500 | 查询参数明确校验 |

旧有 Office/PDF 输入 128 MiB、Office part 16 Mi 字符、输出 32 Mi 字符/200000 段护栏保留。源文件前后大小/修改时间变化时保守放弃当前文件；这不是一致性快照，同长同时间变化仍可能遗漏。

## 测量口径

- 使用工具新建且带清单的原创目录；不向用户现有文件夹生成或清理语料。每个场景记录实际规模、预期与实际计数及 hash/mtime。
- 小文件目录、大日志、八格式混合目录作为正常负载；超长行/字段、密集匹配、整轮预算和错误洪流作为边界负载。取消单独测量，不用极严固定毫秒断言当正确性测试。
- 区分新进程首轮与同进程重复搜索；不清空 OS 文件缓存，不把首轮叫真正冷缓存。进程峰值是该进程生命周期累计，不能当成某一次搜索增量；各场景尽量用独立进程。
- 可比较的旧 Core 文本基线仅使用其原有 API，不拿新增超限行为当速度优化。源码、二进制哈希、工具版本、机器基础信息与测量脚本保留在开发证据中。
- 实际 GUI 单列启动可交互、刷新间隔、长列表滚动、取消完成及聚合诊断；不把 Headless 结构测试当成人工 IME/DPI 验收。

## 仍保留

本阶段不加入 OCR、全文缓存、索引、正则或安装包，不做公开发布就绪声明。Office 保护视图、多实例/版本矩阵、无 Office 干净机及完整人工 IME/多 DPI 验收，具备环境时才标完成。同步第三方解析调用的取消延迟、共享修改文件非快照、依赖库峰值内存继续明确披露。
