# 搜索性能与内存治理计划

日期：2026-11-13。状态：已完成。依据：用户反馈搜索慢、要求防范 OOM、缩短 EXE 名称并核查 GitHub 同步状态。982 项完整回归、最终包实窗、前后性能测量及浅目录更新通过，详见[验收报告](performance-memory-results.md)。

## 范围与验收

1. 用已交付 rc.6 原始二进制测量原创 5,000 小文件、64 MiB 日志、八格式混合、密集命中和全局预算场景；新版用相同语料、独立进程和三轮口径比较。完整性校验不计入搜索耗时，未清 OS 缓存，首轮不称冷启动。
2. 根据代码与测量减少搜索循环分配、桌面结果消费开销；保留文件级表达式、完整文件原子发布、来源检查、两层虚拟化、分页、取消和有界背压。
3. 在匹配上下文/正则命中文字分配前检查单文件字符预算，完整文件发布前检查全局已保留字符预算；在 Office 解压前增加单 entry / 总展开量预检。验证密集与长命中、边界/超一项、取消以及重复搜索。字符预算、ZIP 元数据检查均不等于第三方解析器或进程的硬内存上限，不用捕获 OOM 冒充预防。
4. 正式启动名改为 `DocSearch.exe`，同步资源 URI、构建、验证和便携说明；保持项目命名空间与查询/设置语义。
5. 完整回归、独立便携包实窗与峰值/分配对比通过后更新浅目录成品，保留原 rc.6 可回滚版本。

## Git / GitHub 状态

本轮只读执行 `git rev-parse --show-toplevel`，实际返回 `fatal: not a git repository (or any of the parent directories): .git`。当前项目目录没有 Git 元数据；贡献说明也记录尚未配置公开仓库。尚无已识别的远端 URL 可供核对推送日期。本轮不执行 `git init`、commit 或 push。

## 实施边界

不新增 NuGet、索引、跨次全文缓存或 OCR；不继续原文件自动填词调试，不调整个人程序、系统防护、Hosts 或服务。只在项目原创语料上施加压力并记录真实结果；不宣称彻底消除任意输入引起 OOM 的可能性。
