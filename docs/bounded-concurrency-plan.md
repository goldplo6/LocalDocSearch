# 受限并发提取对照实验

日期：2026-11-13。状态：已完成。用户授权先做 1／2／4 工作者对照，实际应用场景不固定；1247 项完整回归、90 个引擎性能样本、39 次独立内容验证、18 次 CLI 控制、12 个原生控制场景和 18 次实窗计时通过。默认仍为 1，已交付浅目录成品保持原样；结论及负面数据见[验收报告](bounded-concurrency-results.md)。

## 实验问题

同一语料、同一查询与结果语义下，受限文件并行是否缩短整轮耗时和首结果延迟，代价是多少累计分配与进程寿命工作集峰值？复杂文档的同步提取是否影响暂停／停止确认？单个大文件不会因增加文件工作者而自动拆分，需保留这类负面控制。

## 实现边界

- 引擎显式可选实验并发数仅 1、2、4，默认 1 继续走原串行路径；不引入缓存、索引、OCR、新 NuGet 或持久化设置。
- 目录由单协调器遍历，完整文件独立提取／匹配；协调器按发现顺序发布并执行全局预算与问题统计。工作中及等待顺序发布的文件总数有明确上限，避免无界重排。
- 每个文件保留严格编码、公式、真实来源、完整读取、修改检测和既有资源上限；全局预算不可由多个工作者竞争突破。取消／失败／限额后等待本轮启动的全部任务退出，不留后台解析。
- 暂停必须等所有活动工作者到达检查点，界面排空已接收结果后才确认；停止解除等待并保留已展示的完整文件。同步解析仍有响应粒度。
- 同时处理多个文件会增加存活解析器和暂存结果。单文件预算乘以并发数也不是进程硬内存上限；不会把累计分配下降称为峰值下降。
- 生产提取器按调用打开独立只读文件／文档对象；实验需真实混合格式与错误文档覆盖。外部自定义提取器若共享可变状态，需要自行保证并发调用安全，默认串行不改变其约定。

## 对照与验收

1. 确定性回归：实际同时执行且不超过 W，顺序、内容、公式、预算、错误和取消一致；慢工作者未暂停时不得误报，停止后没有遗留任务。
2. CLI 使用同一实验二进制与现有原创语料，按 1→2→4→4→2→1 串行启动独立进程，每组 3 轮，每模式 6 样本。覆盖小文件、大日志、混合格式、单文件密集命中与全局预算。
3. 比较结果内容／顺序摘要，不只比较命中计数；摘要在性能轮结束后的独立同工作者搜索中计算，性能回调只计数与记录首结果，避免序列化成为串行瓶颈。校验语料前后哈希与时间戳；完整性检查在计时外，可能预热系统缓存，不称冷缓存。
4. 记录耗时、首结果、GC 累计分配增量和进程寿命工作集峰值，保留所有原始样本与变慢数据。试验顺序、CPU／运行时、二进制与源码快照需要可追溯。
5. 显式实验启动参数连接同一界面，在 1／2／4 下执行暂停冻结、继续完成、暂停停止、运行停止与重搜；另按 1→2→4→4→2→1、每组 3 次独立应用进程测量 5000 文件端到端耗时，区分引擎吞吐与界面等待。所有组检查源文件不变及自有窗口正常关闭。
6. 汇总适用范围和不确定性；若收益不足或代价偏高，保持串行默认，不强行选一个通用并发数。
