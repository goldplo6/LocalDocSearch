# UI 首屏懒加载与 CSV 解析优化计划

日期：2026-11-15。状态：实现、完整回归、最终包对照与原生验收完成，详见[结果与取舍](ui-csv-optimization-results.md)。基线为已验收 rc.10；本轮不提交或推送，不替换旧运行目录。

## 范围和取舍

1. 文件结果构造时保留完整 `FileResult` 和首条摘要，不立即创建最多 50 条匹配包装。首次展开时初始化第一页；折叠、重开、容器回收和后续分页保留已有页面。
2. CSV 保留有界字符缓冲和现有状态机语义，移除逐字符异步调用链；仅缓冲补充进行异步读取。保留 CRLF/CR 规范化、来源行号、字段预算、严格编码、取消、晚段失败和完整文件发布。
3. 元数据发现分类、开始快照、无命中 EOF 检查保持；不将缓存枚举属性当作实时分类。Excel 数字坐标去重、编码策略、纯文本专用扫描、缓存和索引不混入本轮。

## 测量

- 旧版本使用 rc.10 成品。CSV 新旧共用同一个新基准驱动，仅替换实际发布的 Core 库；其他文件哈希一致，结果摘要与完整性核验在计时外进行。
- CSV 使用原创普通多字段及带引号、逗号、转义与多行的语料，分别测提取端到端和完整引擎搜索。提取计时包含文件读取、解码和解析，不冒称纯解析时间。
- UI 分别测既有 5,000 文件/10,000 匹配语料，以及更多折叠匹配包装的有界原创密集语料。每轮独立应用进程和设置文件，记录内部交付耗时、外部 UIA 观测、CPU 和内存。
- ABBA 串行交替，保留原始正负样本。不清操作系统缓存，不称冷启动；累计分配、存活内存和进程寿命峰值分别解释。
- 生产热路径不为测量加入逐字符/逐匹配计时。当前阶段用提取工具、完整引擎和实际窗口三种独立口径定位收益，三者不能相减当作精确阶段耗时。

## 验收

- 懒加载：构造为零包装、程序展开、第一页边界、提前分页、重复展开和回收；保留旧末项触底、加载更多、视口定位、暂停/停止及预览覆盖。
- CSV：旧算法差分、8192 字符附近边界、跨块 CRLF、引号和转义、空字段与 EOF、预算、取消、错误消息和错误前已枚举前缀。
- 六套完整回归及锁定依赖构建；候选包实际原生搜索、预览与滚动。核对旧包及源样本不变。
- 各项单独报告。仅在结果一致且有资源/交付改善依据时保留优化；未确认的速度收益写明，不按单次毫秒差异宣称普遍提速。
