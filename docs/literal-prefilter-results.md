# 多关键词候选预筛：可行性、实现与验收

日期：2026-11-14。状态：已完成算法对照、完整构建、1453 项回归和 rc.9 真实窗口验证；独立终核记录见下文。[实施计划](literal-prefilter-plan.md)。

## 判断与本轮取舍

依据[搜索实现原理](search-principles-and-next-steps.md)、[受限并发实验](bounded-concurrency-results.md)和现有源码，选择先减少多关键词对确定无候选片段的重复扫描。

- 实施任一词候选预筛，继续使用原来的逐词命中枚举、上下文构造及排序。
- 直接把完整片段保存到 EOF 再构造上下文，会让稀疏命中的大段长期驻留；当前结果字符预算没有覆盖这些整段原文。本轮保留原有构造时机，后续紧凑存储须独立设计和测量。
- 默认并发保持 1，已有 1／2／4 显式实验入口保留。多文件并发与本轮多词优化解决不同开销，已有实验不足以支持所有场景默认 4。
- 维持每轮重新提取源文件，不新增跨次正文缓存、全文索引、OCR 或 NuGet 依赖。

## 精确实现

[引擎实现](../src/LocalDocSearch.Core/TextSearchEngine.cs)在查询快照完成及词表按原比较方式去重后，对 **至少 32 个不同词**创建一次 `SearchValues<string>`，供本轮只读共享。当前提取片段至少 **256 个 UTF-16 字符**时，先求任一词的最早位置；返回 -1 只跳过该片段的逐词循环，否则从这一最早位置开始原逐词 `IndexOf`。

这是候选过滤，完整文件仍继续读取。晚段错误、警告、长度及元数据复核、单文件与全局预算、AND／OR／括号公式、同词非重叠和不同词独立重叠、匹配排序及来源定位沿用原契约。正则使用原路径。少词或短片段不执行候选预筛。

参考官方 API：[SearchValues.Create](https://learn.microsoft.com/en-us/dotnet/api/system.buffers.searchvalues.create?view=net-10.0)、[MemoryExtensions.IndexOfAny](https://learn.microsoft.com/en-us/dotnet/api/system.memoryextensions.indexofany?view=net-10.0)。

## 门槛来自正负对照

初版门槛为 4 词。[初版原始报告](../artifacts/literal-prefilter-measurement-7d4c464addc34fd1b087a10c93d0bffc/summary.json)中，4 词无命中中位耗时 8.46→9.91ms，16 词无命中 9.47→12.11ms，16 词稀疏与密集场景也回退；64 词无命中 17.08→10.45ms。于是收紧到 32 词，并补充 32／64 词和中文语料后复测。原始负面结果保留，未覆盖。

最终[交替对照报告](../artifacts/literal-prefilter-measurement-4920b66b139c4c0cbdc55f0fee04ea05/summary.json)：同一最新驱动和依赖复制为 old／new 两套，仅 old 的 Core 替换为已通过 1247 项回归的优化前版本；14 个旧 Core 源输入逐 SHA 校验并与 Git 初始提交核对。按 old→new→new→old，每场景每组独立进程、每进程 3 轮。15 场景共 **180 个计时样本、60 个独立内容验证轮**，每版每场景 6 个计时样本。完整结果内容与发布顺序 SHA、状态、文件及匹配计数、语料 SHA 均相同。

语料共 5 文件、10 MiB，ASCII 无命中／稀疏／密集／短行及中文长行各一类；32／64 词命中查询仍只有 16 个实际出现的词。中文是受控合成语料，不能据此推断所有中文 Office／PDF 文档的端到端速度。计时包括词表、请求和查询预处理，完整匹配摘要在独立验证轮计算，排除在计时与累计分配之外。来源完整性核验在计时外，但会预热系统缓存；没有清理 OS 缓存或强制 GC。

### CPU、分配与峰值

- 32 词无命中 CPU 中位数 46.875→31.25ms；32 词密集 46.875→54.6875ms，后者虽墙钟时间减少，CPU 增加。
- 64 词无命中 CPU 62.5→54.6875ms；中文无命中 132.8125→46.875ms，中文稀疏 203.125→46.875ms。短任务 CPU 计量粒度明显，原始样本保留。
- 受影响的 32／64 词场景每轮累计分配约增加 17.8～37.5KB，包含查询级候选结构等成本；不是减少累计分配的优化。
- 进程寿命工作集高水位中位数：ASCII 64 词无命中约 84.40→85.05MiB，中文无命中约 80.24→79.43MiB；短片段对照约 86.92→93.43MiB。测量范围包含运行时、JIT、来源核验和独立摘要轮，非每轮新增内存，也非产品硬内存上限。本轮没有普遍降低峰值内存的证据。

## 复测入口

- [交替测量脚本](../scripts/measure-literal-prefilter.ps1)：`-DriverDirectory <当前基准输出目录>`，默认引用本机保留的优化前 baseline；先检查脚本中的 baseline 路径和 SHA。
- [基准驱动说明](../tools/LocalDocSearch.Benchmarks/README.md)：`literal-prepare` 创建独立语料，`literal-run` 执行指定场景。quick 语料只用于契约测试，正式矩阵用标准 10MiB 语料。
- [原生窗口验证脚本](../scripts/verify-literal-prefilter-uia.ps1)：`-Executable <候选包内 DocSearch.exe>`，仅自有进程、独立设置和原创语料。
- [最终审计脚本](../scripts/verify-literal-prefilter.ps1)：候选目录、测量摘要、原生报告三项明确输入；核对真实 TRX、源码及锁、原始样本／内容摘要、包与旧成品哈希、文档链接和进程退出。

本轮未新增系统真实 IME、跨屏、干净机、杀毒兼容、签名或公开发布验收；原文件自动填词调试继续停止。没有把第三方同步解析的响应粒度或内存预算表述为硬保证。
