# 第四阶段：可靠性与性能基线验证报告

日期：2026-11-09。状态：本阶段计划、实现与下列验收完成。范围依据[第四阶段计划](phase-4-plan.md)。这是一台开发机上的可复现基线，保留性能回退、访问能力和人工待测项。

## 实现结果

1. **有界提取与原子发布**：物理行、CSV 字段、第三方片段统一执行 UTF-16 长度预算；分配上下文与命中对象之前检查匹配预算。单文件超限整份放弃，正常文件继续；全局预算保留已经完整发布的文件，出现额外合格项时才标记 `Limited`。恰好达到上限且没有额外项时仍可完成。
2. **扫描与诊断治理**：限制候选文件、命中文件、匹配总数、目录深度与待扫描目录。错误/警告原始总数与保留详情分离，省略次数不重复累加。文件提取前后大小或修改时间变化时放弃该文件；这仍是非快照读取。
3. **桌面背压与响应**：结果通道容量 64、诊断通道容量 256，满时等待；界面按 60 ms 节拍消费，结果处理约 4 ms、总处理约 8 ms 的软时间片。取消解除结果写入等待，逐项停止新增结果，已接收诊断及最终聚合说明继续排空。最终重排仅发一次集合 Reset。匹配与诊断列表采用虚拟化视口，匹配仍每次增加 50 条。
4. **主动聚合诊断**：显示端到端耗时、完整错误/警告/省略数、观察到的最长界面刷新间隔。用户主动复制 JSON 时只包含计数、限额、运行时和基础系统信息，排除目录、文件路径、关键词、正文、异常原文及原始限制原因；不自动写日志或发送遥测。保留详情的代码分布不冒充全部错误的分类统计。
5. **实测驱动修正**：补上四种文档适配器的单段预算；补上错误 XLSX 根节点触发的 `InvalidDataException` 隔离；复用并清理文本缓冲、优化分隔符扫描；给文件行提供可读的辅助功能名称。

资源默认值见[资源策略实现](../src/LocalDocSearch.Core/SearchResourceLimits.cs)：单段 1,048,576 字符、每文件 50,000 处、整轮 200,000 处/20,000 命中文件、100,000 候选文件、20,000 待扫描目录、深度 128、1,000 条全局诊断详情及每文件 100 条警告详情。全局另可保留一条省略聚合说明；关键词最多 64 个、每词 4,096 字符、每侧上下文 0–500 字符。旧有 Office/PDF 输入 128 MiB、Office part 16 Mi 字符、累计输出 32 Mi 字符/200000 段限制保留。

以上是应用数据结构与输出预算；第三方同步解析、解压、字体/图片解码及进程整体峰值另有开销。单个同步解析调用仍可能延迟取消。

## 原创语料与测量口径

[基准工具及使用说明](../tools/LocalDocSearch.Benchmarks/README.md)提供 `prepare` 和 `run`。只在新建或空目录生成原创语料；所有权标记与清单记录相对路径、长度、修改时间和 SHA-256。运行前后逐份核验，遇到未登记内容、链接、清单穿越或已有输出文件时停止，不覆盖、删除或修复用户文件。

| 语料 | 数据文件数 | 数据字节 | 主日志行数 / 匹配处数 |
|---|---:|---:|---:|
| [standard-64](../artifacts/phase-4-corpus-standard-64) | 6,453 | 71,756,853 | 633,098 / 78 |
| [quick-128](../artifacts/phase-4-corpus-quick-128) | 1,558 | 138,572,589 | 1,266,195 / 155 |
| [quick-256](../artifacts/phase-4-corpus-quick-256) | 1,558 | 272,790,319 | 2,532,390 / 310 |

各目录另有两份控制文件。64/128/256 MiB 是日志生成目标，实际日志为 67,108,934 / 134,217,755 / 268,435,510 字节。正常小文件场景为 5,000 份文件、10,000 处；混合目录为 25 套八格式、200 份文件、400 处。

同场景使用独立 CLI 进程，串行搜索三轮；第一轮单列，重复值是后两轮的中位数（两个数的平均值）。运行前完整性校验会读取文件，未清理 OS 缓存，第一轮不代表真正冷缓存。搜索计时排除前后完整性校验和准备过程。

基准回调只计数而不长期持有结果；窗口会保留匹配、上下文和 ViewModel，另测。峰值 Working Set 是单个场景进程生命周期累计值；托管分配是搜索测量段总分配增量的三轮中位数，分配量不等于同时在用内存。不强制 GC，也不设固定毫秒/内存断言。

## 真实桌面验收

[UIA 验收脚本](../artifacts/phase-4-uia-smoke.ps1)启动实际 Release 窗口，以独立配置隔离用户偏好。最终[窗口验收数据](../artifacts/phase-4-desktop-uia.json)记录进程 42712、DPI 120（125%），仅代表本机这一个 DPI 点。

另以[启动脚本](../artifacts/phase-4-startup-uia.ps1)单独测量三个新进程：从进程启动请求到 UIA 读到启用的设置按钮和目录输入框，分别为 **1,570.68 / 1,441.38 / 1,385.49 ms**，中位数 **1,441.38 ms**。含 20 ms 轮询开销，未清 OS 缓存，亦不代表首次安装后的冷启动。每轮使用独立配置，三个进程均正常关闭，数据见[启动结果](../artifacts/phase-4-startup-uia.json)。

| 操作 | 窗口自身端到端耗时 | 最长观察刷新间隔 | 结果 |
|---|---:|---:|---|
| 5,000 文件 / 10,000 处 | 4,677 ms | 66 ms | 正常完成；先取到首批可见行，再以本应用可见控件取得焦点并发送 End，确认末文件出现；前后各只实现 2 个文件行 |
| 全局 200,000 处 | 177 ms | 62 ms | 40 份完整文件；明确资源上限与扫描未完成 |
| 1,200 个读取错误 | 583 ms | 69 ms | 原始错误 1,200、详情省略 200；正常文件保留 |
| 256 MiB 日志请求中取消 | 105 ms 总时长 | 61 ms | Cancelled，取消完成后结果稳定；该次文件尚未完整提取发布 |
| 取消后再搜 5,000 文件 | 4,710 ms | 72 ms | 再次完成 5,000 / 10,000 |

UIA 外部从取消命令到观察到完成为 **61.36 ms**，含命令与 60 ms 轮询开销，不是解析器中断保证。界面最长刷新间隔包括计时器调度，亦不是单个渲染帧的持续时间。

首个 5,000 文件场景的进程生命周期峰值为 192.33 MiB；全局场景后为 242.91 MiB；整个窗口验收结束前为 248.16 MiB。这些值包含保留结果与 UI，且同一进程累计，不与 Core 独立进程数据混用。

实际发现文件行辅助功能名称原先为 ViewModel 类型名，已使用原生 ItemContainerTheme 绑定可读标题，新增回归并在实际窗口确认。外层列表的 UIA ScrollPattern 仍报告不可滚动/百分比 -1，因此本轮明确采用可见文件控件焦点 + 实际 End 键路径，而非声称 ScrollPattern 验收通过；滚轮、完整键盘和辅助功能能力矩阵继续单列。

复制聚合诊断按钮启用；JSON 脱敏由回归验证，实机未改动用户剪贴板。测试进程正常关闭。保存了三张本应用前景窗口截图；本会话图像读取能力未启用，截图视觉审阅留待人工，不把截图保存视为视觉验收。

## Windows 文件系统与异常隔离

[文件系统脚本](../artifacts/phase-4-filesystem-probe.ps1)只在独立原创目录施加 NTFS ACL 和目录联接，使用[小型只读探针](../artifacts/phase-4-filesystem-probe/Program.cs)调用正式 Core。最终[文件系统结果](../artifacts/phase-4-filesystem.json)六组均通过：

- **460 个 UTF-16 单元的完整中文路径**：正常搜索，1 文件 / 1 处，Completed。
- **真实 NTFS junction 目录循环**：链接被跳过，不重复遍历；正常文件 1 / 1，Partial，问题 1。
- **根目录是 junction、根目录祖先是 junction**：两种入口均在参数验证阶段停止。
- **真实 ACL 拒绝单文件 ReadData**：其它文件继续，AccessDenied，Partial；扫描 2 份、命中 1 份。
- **真实 ACL 拒绝子目录 ListDirectory**：其它文件继续，AccessDenied，Partial；正常文件 1 / 1。

源数据共六份，前后 SHA-256、长度、修改时间不变；原文件及目录 ACL 恢复核对一致，测试 junction 已核验目标后仅删除联接本身。其它原始测试文件保留。损坏 Office/PDF、独占锁、取消/失败后的句柄释放及重新独占打开由适配器和 Core 回归覆盖。来源长度或修改时间变化的整文件放弃由回归验证；同长同时间变更与检查后的竞争窗口仍是边界。

## 使用与复现

日常仍按[项目说明](../README.md)启动应用。在原目录搜索时先保留默认预算；出现资源上限请缩小目录或提高关键词精度。界面尚未提供预算编辑，开发者可通过不可变 `SearchResourceLimits` 注入；设置中的编码、范围、上下文与排序保持原功能。

```powershell
# 先 Build；以下目录必须新建或为空，输出文件必须尚不存在。
./.tools/dotnet/dotnet.exe tools/LocalDocSearch.Benchmarks/bin/Release/net10.0/LocalDocSearch.Benchmarks.dll prepare artifacts/repro-owned --log-mib 64
./.tools/dotnet/dotnet.exe tools/LocalDocSearch.Benchmarks/bin/Release/net10.0/LocalDocSearch.Benchmarks.dll run artifacts/repro-owned many-small --repeat 3 --output artifacts/repro-many-small.json
./.tools/dotnet/dotnet.exe tools/LocalDocSearch.Benchmarks/bin/Release/net10.0/LocalDocSearch.Benchmarks.dll run artifacts/repro-owned errors --repeat 3 --output artifacts/repro-errors.json
```

[顺序运行记录脚本](../artifacts/phase-4-run-benchmarks.ps1)及所有原始报告保留供审计；固定输出已有时会停止，再次测量请换新输出名，不清除原证据。当前窗口、文件系统脚本也保留已存在报告，避免覆盖。
