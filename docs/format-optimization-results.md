## 候选与语义约束

| 格式 | 本轮试验 | 采纳状态 |
|---|---|---|
| TXT / MD / LOG | 试验延迟创建行拼接 StringBuilder，保留原解码与取消边界 | 收益波动、分配仅相差数百字节，已撤回，源码与 rc.11 相同 |
| CSV | 普通及引号内连续文字在原 8192 字符 buffer 内找特殊字符，逐字符检查取消和预算后批量追加 span | 采纳；最终普通、引号、跨块场景均有收益 |
| XLSX | shared strings 和 worksheet 用 SAX 完整预检，再逐 si / cell 小 DOM 读取 | 采纳；耗时与寿命工作集峰值下降，但累计分配增加 |
| DOCX | XML 完整预检，正文逐段、表格逐行小 DOM，保留嵌套表 DFS 与包装层遍历 | 采纳；表格收益明显，正文有一项稀疏搜索慢 3.09%，保留该回退 |
| PPTX | 单 run 或无文字贡献的简单段落快路径，先检查原 UTF-16 单段与累计预算 | 采纳；本组耗时与累计分配下降 |
| PDF / Office 共享缓冲 | 完整解析成功后，逐段消费时清除已消费的列表引用 | 采纳消费期资源修正；PDF 提取算法未改，无稳定提速结论 |

直接 Decoder 和按字节替代原 UTF-8 预验证暂缓：它们会改变 StreamReader 的 read-ahead、晚期解码失败前已发布片段，以及原字符填满读取的取消边界。本轮先用独立旧算法参考固定这些行为，没有以放宽契约换取速度。

Excel 保留原地址字符串去重（包括空白单元格及末尾 LF 差异）、CurrentCulture 坐标转换、隐藏表编号和公式缓存值。SAX 仍遵守每 part 字符预算与单文件完整提取；完整预检用于维持晚损坏 XML / part 预算优先于早期业务警告或段预算的原顺序，代价是两遍解析，需要实测 CPU 与内存权衡。

Word 保留正文和单元格段号、嵌套表 DFS 编号、GridBefore / GridSpan、包装层与排除树；PPTX 不扩大到组内或其它后代文字。所有格式继续保留 ID、文字、来源、顺序、警告、异常及文件发布原子性。

## 性能与最终验收

初轮已完成 45 场景、180 个独立进程组、540 次计时及 540 次计时外完整核验。末尾二进制比较器因 PowerShell 对 OrderedDictionary 的属性排序产生错误顺序，原始报告保持 `passed=false / Staged binary drift.`；独立 reconciliation 按精确路径核验两组共 48 个文件、全部 2700 对有序摘要、原始数组与中位数、来源和 217 项源码戳，确认实际字节没有漂移，并保存单独通过回执，没有改写原报告。比较器已改为显式取路径排序，最终候选必须重新得到自身 `passed=true` 的完整测量。

初轮 XLSX 约快 18%—26%，DOCX 约快 10%—24%，PPTX 约快 12%—27%；这些是候选筛选数据，最终以实际发布包重测为准。Excel 的进程寿命峰值下降，但累计分配增加约 51—70 MB，不能概括为所有内存指标都下降。

CSV 首轮普通字段约快 61%—69%，引号字段却慢约 8%—11%。将引号内连续普通文字也纳入 span 路径，保留引号、CR/LF、预算和取消逐字符边界后，独立 12 场景复测通过：普通 CSV 约快 63%—68%，引号 CSV 约快 53%—57%，跨块 CSV 约快 29%—33%。复测证据为本地 `artifacts/format-measurement-46ea7a84db794b1c9942e6fc8f5235a1/summary.json`，没有混入首轮样本。

PDF 两轮耗时均有明显启动/JIT 波动：首轮纯提取慢约 67%，复测约慢 6%，无命中与稀疏命中方向也互换，因此没有稳定提速结论。PDF 解析与阅读顺序算法保持原样；仅随 Office 共享已验证的消费引用释放，不把托管存活量、可回收性或进程寿命峰值当作完整提取峰值。

### 资源代价与消费引用

以下取直接提取场景的 6 样本中位数，单位 MiB。**累计分配**是本轮进程 GC 分配增量；**寿命峰值**是进程工作集累计峰值，包含同进程此前轮次与验证，不是每轮或单独提取峰值：

| 格式 | 累计分配 rc.11 → rc.12 | 工作集寿命峰值 rc.11 → rc.12 |
|---|---:|---:|
| XLSX 共享字符串 | 198.065 → 264.524 | 231.012 → 125.199 |
| XLSX 内联字符串 | 185.029 → 233.847 | 218.248 → 127.473 |
| DOCX 普通段落 | 42.156 → 42.423 | 121.002 → 92.393 |
| DOCX 表格 | 51.439 → 51.419 | 146.957 → 91.039 |
| PPTX | 42.779 → 28.050 | 128.559 → 112.391 |
| PDF | 169.273 → 169.276 | 80.332 → 79.484 |

Excel 的两遍 XML 处理加小 DOM 增加约 49—66 MiB 累计分配，换取本组耗时和工作集寿命峰值下降；这是明确的空间／分配权衡。Word 累计分配基本持平，PPTX 累计分配约少 14.7 MiB。没有观察到所有格式、所有内存指标一起下降。

另在计时之外完整枚举，在首段、一半和四分之三处强制 GC，只保留当前段。两次独立观测取中位数，展示四分之三处的托管存活量：XLSX 共享字符串 34.003 → 9.828 MiB、内联字符串 33.972 → 9.793 MiB、Word 段落 12.974 → 3.956 MiB、Word 表格 13.342 → 4.083 MiB、PPTX 10.887 → 3.458 MiB、PDF 4.757 → 4.156 MiB。首段时存活量仍基本相同；这验证的是已消费引用能逐步回收，**不是完整提取峰值降低，也不代表操作系统会立即归还相同工作集**。强制 GC 没有放进计时路径。
